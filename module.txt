# CUDA LP/QP Solver — Final Module Specification (v3)

**Status: LOCKED (v3, 2026-09-01).** Changes require team agreement.


Each module has one job and uses the shared project types.

## Changes from v3 (post-lock)
- Added Module 22: Branch-and-Bound (MILP). Not in v3's scope -- v3 covers LP/QP
  only. Recorded as its own module, not folded into an existing one, per "no
  module silently implements another module's job" below.
- Module 22 extended: point-based warm start across nodes (new
  `model::forward_map_to_canonical_hint`, the original-to-canonical-space
  inverse of `recover_solution`), MILP-specific GCD/knapsack presolve
  (`MilpPresolve.hpp`), and root-level knapsack cover cuts.
- Module 22 further extended: equality-row absorbing-singleton elimination
  (`eliminate_equality_row_absorbing_singletons`), needed because
  markshare_4_0.mps's every row mixes one continuous "deviation" column
  with otherwise-discrete columns, which silently blocked BOTH the GCD rule
  and cover-cut separation (both require an all-discrete row). Caught and
  fixed a real bug during development: the eliminated column's cost must be
  ALGEBRAICALLY FOLDED into the remaining columns before it becomes a
  zero-cost empty column, not left for the generic empty-column rule to fix
  in isolation -- doing that wrong let the solver report a confidently
  WRONG proof of optimality (objective 0.0, when the true optimum is
  unreachable at that value) rather than an honest "still searching." A
  confidently wrong answer is a worse failure than a slow correct one.

- Added Module 23: Revised Simplex (2026-09-13). See the section below. Like
  Module 22 it is recorded as its own module rather than folded into Module 12
  (Linear Solver): Module 12 solves a Newton system for the IPM, Module 23 is a
  second complete LP algorithm with its own basis, its own factorization and its
  own termination certificates. This also makes `SolverStatus::Infeasible` and
  `SolverStatus::Unbounded` reachable from the solver for the first time -- until
  now `Infeasible` came only from the canonicalizer and `Unbounded` was never
  returned at all.

- Added Module 24: PDLP, primal-dual hybrid gradient for LP (2026-09-14). A
  THIRD LP engine and the first first-order method here. No factorization at
  all -- its inner loop is one `K` and one `K'` product and nothing else, which
  is the only operation this hardware's FP64 penalty leaves competitive
  (docs/ARCHITECTURE-REVIEW.md 3.5 measures factorization at ~64x slower than
  the CPU, SpMV at ~2x).
- Added Module 25: homogeneous self-dual embedding, a FOURTH LP engine,
  `--method=hsd` (2026-09-14/15). Residuals, mu, classification and recovery;
  the iteration control transcribed from Andersen & Andersen (2000); the
  bordered Newton solve, whose general-bounds border the paper does not give
  and which was obtained instead by a change of variables onto the published
  standard-form system; and the loop that runs them. 18/19 on the corpus
  against the direct interior-point path's 6-7/19, and unlike that path it can
  report Infeasible and Unbounded at all.
- Added Module 26: irreducible infeasible subsystem (2026-09-14). Turns the
  verdict "this model is infeasible" into "these rows contradict each other,
  and dropping any one makes the rest satisfiable".

## Changes from v2
- Module 1: `.mps` is implemented; `.lp` is next, then a model writer, then QPLIB.
- Module 2: new contract — output is IPM-startable or a definite infeasibility verdict.
  Gains fixed-variable removal, empty-row resolution, a prohibition on free splitting,
  ranged rows as an equality plus a bounded column, and a maximization negating c, Q and
  the objective constant.
- Module 4: free column singleton substitution; re-checks empty rows, which it creates.
- Module 6: verifies the startability contract before building a SolverState.
- Module 9: owns the unconditional Theta^-1 floor and dual regularization.
- Module 11: escalation only; it does NOT own the floor.
- Module 12: refinement is against the UNREGULARIZED residual.
- Module 17: no global dual sign flip — verified the convention already matches HiGHS.
- Module 3: re-runnable, and MUST be re-run after presolve.
- Module 9: augmented path puts delta_p on the primal block, delta_d on the dual block.
- Module 11: escalation must DECAY back toward the floor, not ratchet.
- Module 17: drops the RANGE column added for a ranged row.
- Module 18: owns stall detection; returns the best iterate, never INFEASIBLE.
- Module 19: records floor activations and refinement passes.

## 1. Input / Problem Loader
Input: filepath. Output: Problem. Implement `Problem loadProblem(const std::string& filepath);`
Preserve objective, objective sense/constant, row/column bounds, names and integrality flags.
Do not canonicalize, presolve, scale or solve. Return useful parse/validation errors with
line and column.

Format order:
1. `.mps` — IMPLEMENTED and verified on 19 Netlib instances (9 dimension-exact). Every
   benchmark the problem statement names ships as MPS.
2. `.lp` — next. CPLEX dialect as the base, accepting Gurobi's superset. Human-readable,
   which matters for demonstration.
3. model writer — dumps any Problem back to MPS. Buys the round-trip test and lets one
   module owner hand another a dumped canonical/presolved model to debug in isolation,
   instead of running the whole upstream pipeline.
4. QPLIB — named in the problem statement, has its own format. MPS-QP (QUADOBJ/QMATRIX)
   already works.

## 2. Canonicalizer
Input: Problem. Output: canonical Problem + TransformRecord.

Use the bounded-variable form: equality rows have no slack; inequality rows get `s>=0`;
finite variable bounds remain native. Never convert an upper bound into a row. All
transformations reversible.

**Contract: the output is startable by the IPM, or a definite infeasibility verdict.** This
must not depend on the Presolver, which can be switched off. Three duties enforce it.

**Remove fixed variables (l_j == u_j).** The IPM needs x-l > 0 AND u-x > 0; their sum is
u-l = 0, so with l = u no strictly interior point exists and the method cannot start. Fixed
variables are constants:
```text
b_E := b_E - A_E[:,j]*l_j
b_I := b_I - A_I[:,j]*l_j
c   := c   + Q[:,j]*l_j                (remaining columns)
objective_constant += c_j*l_j + 1/2*Q_jj*l_j^2
column j deleted
```
Record RemoveFixedVariable(j, l_j). Invert by reinstating x_j = l_j and computing its reduced
cost from the recovered duals. 1067 fixed columns across 8 of 19 corpus instances.

**Resolve empty rows.** An all-zero row makes that row and column of A*Theta*A^T identically
zero for every Theta — an exact zero pivot.
```text
0 = 0  (within tolerance)  -> drop, record RemoveEmptyRow
0 = b, b != 0              -> return INFEASIBLE
```
Never regularize the second case away: that converts a provable infeasibility into
NUMERICAL_FAILURE. 25 empty rows in 80bau3b, 3 in greenbea.

**Do not split free variables.** x = xp - xm is prohibited: it doubles columns, makes the
pair structurally dependent, and converges poorly in IPMs. Free variables stay free and are
handled by the Module 9 floor.

**Ranged rows become an equality plus a bounded column.** `lo <= a'x <= hi` is not
expressible in the one-sided form `A_I x + s = b_I, s >= 0`. Emit instead
```text
a'x + t = hi,      0 <= t <= hi - lo
```
so `s` stays strictly one-sided everywhere and `rsy = -s.*y_I - mu*1` remains
correct as written. Giving `s` a finite upper bound instead would make it
two-sided, needing a second dual plus matching residual, step-length test and mu
term across Modules 6, 7, 8, 9, 14 and 16. Splitting the row into `a'x <= hi` and
`-a'x <= -lo` is worse still: the two rows are negatives, so their 2x2 block in
`A*Theta*A^T` is singular, held together only by a slack diagonal that vanishes
exactly at convergence.

**Negate BOTH c and Q for a maximization.** The canonical form is a minimization.
A concave maximization arrives with Q NEGATIVE semidefinite, and
`max c'x + 1/2 x'Qx` equals `min (-c)'x + 1/2 x'(-Q)x`, so `-Q` is the PSD matrix
the stated scope promises. Negating `c` alone leaves the factorization facing an
indefinite matrix it was told it would never see. Record `NegateObjective`; the
objective constant is negated with them and Module 17 inverts it.

## 3. Matrix Analyzer
**Re-runnable, and it must be re-run.** MatrixAnalysis is a pure function of the matrix
given to it, and goes stale the moment a stage changes that matrix. Module 4 changes
free_columns directly (free column singleton substitution exists to reduce it), and
dense_columns and empty_rows with it. Module 9 must consume the analysis of the model it
will actually factorize -- after presolve and scaling -- not the ingestion-time one.

Input Matrix -> MatrixAnalysis. Compute rows, columns, nnz, density, symmetry, dense columns,
free/fixed column counts, empty rows/columns, singleton rows/columns, value dynamic range,
format and storage information. Support Dense/CSR/CSC. No universal density threshold.

free_columns feeds the Module 9 path choice; fixed_columns and empty_rows feed Modules 2
and 4.

## 4. Presolver
Input Problem -> simplified Problem + TransformRecord. Safe reversible reductions: empty
rows/columns, fixed variables, simple redundant rows, bound tightening, obvious infeasibility.
Preserve reconstruction information.

**Free column singleton substitution.** A free variable appearing in exactly one row is an
explicitly-written slack and substitutes out exactly: the single row determines its value,
so both disappear together. Worth doing -- it is cheap and it removes the pressure at the
source rather than regularizing around it.

MEASURED, and it does not remove most of it. Across the corpus 89 of 381 free columns are
singletons -- 23%. On gas11, 89 of 375. An earlier draft of this spec inferred from the raw
counts (375 free, 351 singleton) that most free columns were this pattern; the intersection
was computed and they are not. The two sets barely overlap: most of gas11's singleton columns
are bounded, and most of its free columns appear in several rows.

So roughly 286 GENUINE free columns still reach the KKT builder on gas11, a third of its 862
columns. That makes the Module 9 Theta^-1 floor the primary mechanism rather than a fallback
for whatever presolve leaves behind, and it is why the floor is unconditional.

**Re-check empty rows after every reduction pass.** This module GENERATES them: fixing a
variable or eliminating a singleton can leave a row with no entries. Module 2 cleared the
model on entry, so any empty row present on exit was created here, and it must be resolved
(dropped, or reported INFEASIBLE) before the model moves on.

The Presolver reduces work; it is not what makes the model solvable. That is Module 2, with
Module 6 verifying.

## 5. Scaler
Input Problem -> scaled Problem + TransformRecord. Scale A,Q,c,row bounds and column bounds
consistently. Preserve inverse scaling. Runs BEFORE regularization parameters are chosen —
delta_p and delta_d are relative to scaled magnitudes.

## 6. Initializer
Input Problem -> SolverState. Initialize x,s,y,z,v strictly inside all active bounds/slacks.
Maintain `x-l>0`, `u-x>0`, `s>0`, `z>0`, `v>0`, `slack_dual(y_I)>0`; equality-row y is
unrestricted. Initialize all Mehrotra fields.

**This module also VERIFIES the startability contract before building a SolverState.** An
O(m+n) scan:
```text
no column with col_lower[j] == col_upper[j]      -> else NUMERICAL_FAILURE, naming column j
no row of A entirely zero                        -> else NUMERICAL_FAILURE, naming row i
```
Module 2 establishes the contract and Module 4 re-establishes it, but neither is the last
module to touch the model, and ANY stage that removes a column can create an empty row by
taking away the last entry some row had.

Measured on our corpus, inside Module 2 itself, one stage before the Presolver runs:

```text
instance    empty rows BEFORE    rows dropped AFTER    created by substitution
gas11               0                    2                      2
80bau3b            25                   27                      2
standata            0                    1                      1
```

Three instances had NO empty row before fixed columns were substituted out. A check made
before the substitution rather than after would have passed a singular model on.

Module 6 is the right owner because it is the module that cannot do its job when the contract
is broken: it is asked to place a point strictly inside every bound, which is impossible for a
fixed column. Fail here, loudly, naming the offending index — not twenty minutes later as an
unexplained factorization breakdown. The scan also catches a violation introduced by any
upstream module, not only the two anticipated.

## 7. Residual Calculator
Input Problem + SolverState. Compute:
```text
rp_E=A_E*x-b_E
rp_I=A_I*x+s-b_I
rd=Q*x+c-A^T*y-z+v
rxz=(x-l).*z-mu*1
ruv=(u-x).*v-mu*1
rsy=-s.*y_I-mu*1
```
Omit pairs for infinite bounds. Return vectors and infinity norms.

## 8. Predictor-Corrector Controller
Implement Mehrotra: affine solve, affine primal/dual steps, mu_aff,
`sigma=clamp((mu_aff/mu)^3,0,1)`, corrector RHS including cross terms for lower/upper/slack
pairs, corrector solve, final directions and separate primal/dual step lengths. Reuse
structure where valid.

## 9. KKT / Newton System Builder
Build the bounded-variable Newton system. Return Matrix + rhs + ReductionDescriptor. Never
hardcode dy universally.

**Build Theta^-1, never Theta.** Inverting a diagonal that can contain zero gives inf, then
NaN through the whole matrix, and NaN compares false against every convergence threshold —
the solve fails silently and reports MAX_ITERATIONS on a solvable problem.
```text
Theta^-1 = X_L^-1 Z + (U-X)^-1 V         term omitted where the bound is infinite
Theta^-1 <- max(Theta^-1, delta_p)       elementwise, WHOLE diagonal, every iteration
Theta    <- (Theta^-1)^-1
```
The floor is applied to the whole diagonal, not only to free columns. A free variable's entry
is zero at iteration 0; the entry of any variable that ends strictly inside its bounds at the
optimum goes to zero as well, since z_j -> 0 and v_j -> 0 there. Same failure, later arrival.

**Dual regularization is separate and equally mandatory:**
```text
(A Theta A^T + D_s + delta_d I) dy = rhs
```
delta_p bounds Theta from above; it cannot help when A is rank deficient, since then
A*Theta*A^T is singular for every Theta.

**In the augmented path, both deltas move into the blocks:**
```text
[ -(Q + Theta^-1 + delta_p I)          A^T           ]
[            A                 (D_s + delta_d I)     ]
```
There Theta^-1 is never inverted, so the floor does not apply -- delta_p replaces it, and
is still mandatory: Q is only positive SEMIdefinite, so a free column where Q is zero gives
the (1,1) block an entirely zero row. delta_d is mandatory for a structural reason of its
own: D_s is zero on every EQUALITY row by construction, so the (2,2) block is singular
across the whole equality block before rank deficiency is even considered. gas11 is 459 of
459 equality rows.

Both together make the matrix quasi-definite, which is what guarantees an LDL^T
factorization exists for ANY symmetric permutation -- and that is exactly what lets Module
10 fix an ordering from the sparsity pattern once and reuse it with no numerical pivoting.
Without them the matrix is only symmetric indefinite and a fixed ordering is unsafe.

LP Q=0: eliminate diagonal complementarity variables and form SPD normal equations in dy.
General non-diagonal QP: augmented/quasi-definite symmetric KKT for LDL^T. Diagonal or
cheaply invertible Q may use dy reduction when advantageous.

**A high free-column share selects the augmented path.** There a zero entry of Theta^-1 is
exact and harmless; the zero only hurts when dx is eliminated. Record the reason in the
ReductionDescriptor.

## 10. Ordering / Symbolic Factorization
Own fill-reducing ordering and symbolic analysis for the reference path; prepare elimination
tree/supernodes where useful. Reuse when the sparsity pattern is unchanged. If the chosen
sparse backend owns analysis/reordering, avoid duplicate work.

## 11. Regularization
Owns ESCALATION only. Detect numerical breakdown, raise delta_p/delta_d above the Module 9
floor when it occurs, return regularization metadata and event counts, provide refinement
hooks.

**This module does NOT own the Module 9 floor.** That floor covers a structural condition
known before iteration 0, which no detector can see: a free variable produces inf/NaN before
any condition estimate exists. Detection is the wrong mechanism for it.

Parameters are scale-aware — set relative to scaled data magnitudes, with configurable floors
in Options. The matrix dynamic range reaches 2.6e11 on gas11 before scaling, so an absolute
constant is meaningless.

**Escalation must decay.** The handoff between this module and Module 9 is:
```text
on breakdown:     delta <- min(delta * escalation_factor, delta_max)  then refactor
on a clean solve: delta <- max(delta / decay_factor, delta_floor)
```
A pure ratchet is wrong: once escalated, every later iteration solves a system perturbed
more than it needs and refinement pays for it in extra passes. If delta reaches delta_max
and the factorization still fails, return NUMERICAL_FAILURE -- past that the direction is
too perturbed to be a Newton step. Record escalations and decays in Diagnostics.

## 12. Linear Solver
Input Matrix + rhs + ReductionDescriptor + symbolic information. LP: SPD/Cholesky-type path.
General QP: symmetric-indefinite LDL^T path. Provide CPU reference, GPU implementation,
residual verification, failure detection and iterative refinement. Use CUDA numerical
libraries only as primitives.

**Refinement is against the UNREGULARIZED residual.** The regularized system is a nearby
problem, not the intended one; refining against the regularized residual converges accurately
to the wrong system. Report the number of passes.

## 13. Newton Direction Recovery
Use ReductionDescriptor. LP normal equations: recover dy, then dx,ds,dz,dv. Augmented QP:
recover/use complete direction set. Never assume dy is always solved. Verify all recovered
directions against the Newton equations.

## 14. Step-Length Calculator
Compute separate `alpha_primal` and `alpha_dual`. Enforce:
```text
lower < x+ap*dx < upper
s+ap*ds > 0
z+ad*dz > 0
v+ad*dv > 0
slack_dual(y_I+ad*dy_I) > 0            // slack_dual(y) = -y
```
Do not constrain equality-row y. Handle infinite bounds and use a safety factor. Use the
slack_dual helper rather than writing the negation inline — a `-y > 0` test is easy to write
backwards.

## 15. State Updater
Update:
```text
x <- x + ap*dx
s <- s + ap*ds
y <- y + ad*dy
z <- z + ad*dz
v <- v + ad*dv
```
Preserve affine/corrector information until Diagnostics records the iteration.

## 16. Mu / Barrier Controller
Compute:
```text
mu = [sum((x-l).*z)+sum((u-x).*v)+sum((-s).*y_I)] / active_pair_count
```
Omit infinite-bound pairs. Compute mu_aff with affine steps and then
`sigma=clamp((mu_aff/mu)^3,0,1)`. Include safeguards.

## 17. Solution Reconstructor
Input canonical solution + TransformRecord. Reverse scaling, presolve and canonicalization in
reverse order. Three canonicalization records to undo, not two:

- `RemoveFixedVariable` — reinstate x_j = l_j and derive its reduced cost from the duals.
- `RemoveEmptyRow` — the row carries a zero dual.
- `BoundedSlack` — the RANGE column added for a ranged row is DROPPED. It is not an
  original variable and has no place in the reported solution. The row's reported slack is
  recomputed from the original activity, not read from that column, so nothing is lost by
  discarding it. Datatypes section 8 assigns TransformRecord the job of recording which
  column belongs to which row; this is the module that consumes it.

Return original variables, original objective and original-space feasibility information.

**Do NOT apply a global dual sign normalization here.** Verified against HiGHS: for a
minimization it reports a NEGATIVE dual for a `<=` row and a POSITIVE one for a `>=` row, and
a positive reduced cost for a variable at its lower bound. That is already this solver's
convention, so no normalization is needed at the exit.

The only sign work is local and already implied by the transform stack: the Canonicalizer
negates `>=` rows, so NegateRow records must flip those duals back during reconstruction.
That flip is what yields the positive `>=` dual. A second, global flip on top would invert
every inequality dual, silently: the duals stay plausible and are simply all backwards
against any reference solver.

## 18. Convergence Checker
**Stall detection has a consumer.** After `stall_iterations` consecutive iterations with no
meaningful progress in the convergence measures, terminate and return the BEST ITERATE
seen, with status MAX_ITERATIONS or NOT_CONVERGED — never INFEASIBLE. Stagnation is
evidence that this run stopped improving, not evidence about the model. That is the whole
of what "do not infer infeasibility from stagnation" leaves room for, and without it
`stall_iterations` is a knob with nothing reading it.

Use relative, scale-aware infinity norms for primal feasibility, dual feasibility and
complementarity/duality gap. Check iteration limit and numerical failure. Do not declare
infeasibility from stagnation — INFEASIBLE comes only from a definite verdict (Module 2).

Guard every comparison against NaN explicitly. `NaN < tol` is false, so a poisoned solve
silently runs to the iteration limit and reports MAX_ITERATIONS on a solvable problem.
Detect non-finite residuals and report NUMERICAL_FAILURE instead.

## 19. Diagnostics
Record residual norms, lower/upper/slack complementarity, mu, mu_aff, sigma, both step
lengths, timings, GPU transfers, regularization events, **theta floor activations**,
**refinement passes**, and status. The floor-activation and refinement counts are the
evidence for any numerical-robustness claim in the submission.

## 20. Logging
Provide concise human-readable iteration output. Keep logging independent from Diagnostics
and mathematics.

## 21. Options / Parameters
Centralize primal/dual/complementarity tolerances, max iterations, `delta_p_floor`,
`delta_d_floor`, `regularization_escalation_factor`, `max_refinement_steps`, safety factor,
ordering policy, linear solver policy, presolve/scaling policy and GPU settings.

## 22. Branch-and-Bound (MILP)
Input Problem with `has_discrete() == true` -> Solution over the discrete variables, or a
definite Infeasible verdict, or the best incumbent found under a node/time limit (status
NotConverged, never Infeasible -- same principle as Module 18: a limit is evidence the
search stopped, not evidence about the model).

**Reuses Module 1-20's entire pipeline UNCHANGED as the per-node relaxation engine.** A
branch-and-bound node is the original Problem with tightened column bounds; solving it is
exactly one call to `solve_problem`. This module adds no new IPM math -- only the search
around it: best-first ordering by relaxation bound, most-fractional branching, and
incumbent/pruning bookkeeping.

Best-first search: pop the node with the most promising relaxation bound first. This is what
lets termination double as a proof of optimality (up to `MilpOptions::gap_tolerance`) rather
than a heuristic cutoff -- once the best remaining bound in the tree cannot beat the
incumbent, none of the rest can either.

A relaxation that returns anything other than `Optimal` (NotConverged, MaxIterations, ...) has
its node PRUNED, not retried -- its bound cannot be trusted, and using an unreliable bound to
cut a subtree risks discarding the true optimum. A relaxation reporting `PrimalInfeasible`
prunes the node normally (an expected, common outcome, not a search failure).

**Point-based warm start.** Each child node solves with a hint built from its immediate
parent's own converged solution (Solve.hpp's `warm_start_x`, `Initializer.hpp`'s `warm_start`),
not a cold bound-midpoint start every time. The real obstacle this had to clear: a child's own
`canonicalize()`+`presolve()` run independently and can legitimately produce a DIFFERENT
canonical shape than its parent's (branching a binary variable to `l==u` newly triggers
`RemoveFixedVariable` for that one column, where it was a plain kept column in the parent) --
so the parent's canonical-space point cannot be handed to the child directly. Solved with
`model::forward_map_to_canonical_hint` (Canonicalizer.cpp): replays the child's OWN transform
stack FORWARD (original space to canonical space -- the inverse direction of `recover_solution`,
built by mirroring its cases so it cannot drift from what recovery actually does) to map the
parent's ORIGINAL-space `x` into the child's own canonical space, one column at a time.
Explicitly scoped to the four transform kinds that currently touch a column's existence or
identity (`KeepColumn`, `RemoveFixedVariable`, `RemoveFreeSingleton`, `MergeDuplicateColumn`) --
`TightenBound`/`ShiftVariable`/`NegateVariable` are declared in Transform.hpp but never pushed
by the current Presolver. A column this cannot map safely is left unhinted (Initializer falls
back to bound-midpoint for it alone) rather than guessed at. Only the PRIMAL point is
warm-started this way -- `s`/`y`/`z`/`v` are still derived fresh from the warm-started `x` by
Initializer's existing logic, not carried over themselves, since they depend on ROW structure
too and the same shape-mismatch risk applies there with less payoff for the added risk.

**MILP-specific presolve: GCD/knapsack row tightening** (`MilpPresolve.hpp`, run once on the
root before the search begins). For a row where every nonzero column is discrete with an
exact-integer coefficient, any integer combination is necessarily a multiple of
`g = gcd(|a_j|)` -- a finite bound rounds to the nearest multiple of `g` with no integer point
lost, and a bound that isn't itself a multiple of `g` on an equality row is a PROVABLE
infeasibility, caught before a single relaxation is solved.

**Knapsack cover cuts** (generated in `solve()`'s root cutting loop, "cut-and-branch": derived
once against the root relaxation, then held fixed through the whole search -- not regenerated
per node, which would be full branch-and-cut). Greedy separation (Wolsey's standard heuristic,
not exact minimum-weight-cover separation, and the cut is not lifted): for a `<=` row over
binary columns with positive coefficients, greedily builds a cover by adding columns in
descending order of their current LP value until the coefficient sum exceeds the row's bound,
then adds `sum x_j <= |cover|-1` if that inequality is actually violated by the relaxation's
point. Every such cut is globally valid, so generating it once at the root is sound everywhere
in the tree. Rows needing variable complementation (a negative coefficient) are skipped, not
attempted.

Eligibility ("is this column effectively 0/1") checks `col_type == Binary` OR `col_type ==
Integer with bounds exactly [0,1]` (`is_binary_like`, BranchAndBound.cu). Checking `== Binary`
alone was a real, caught bug: MPS has no dedicated binary bound type outside the explicit `BV`
marker (MpsReader.cpp) -- a column declared `INTORG ... UP bnd x 1` (integer, implicit lower 0,
explicit upper 1) is tagged `Integer`, not `Binary`, even though it behaves as one. This is
EXACTLY how markshare_4_0.mps declares all 30 of its variables, so the strict check silently
rejected every row of it, and cover-cut separation never fired on that file at all until fixed.

**Cross-row (aggregated) cutting.** A single row's own cover/GCD structure can be too weak to
expose anything useful -- confirmed on markshare_4_0.mps, whose 4 knapsack rows over the SAME 30
binary columns are each individually weak. A nonnegative (all-ones) combination of several valid
`<=` rows is still a valid inequality, and the AGGREGATE can reveal a cover or GCD structure none
of the individual rows shows alone -- a standard technique (surrogate/aggregated constraints) for
exactly this instance family. Implemented as full power-set enumeration (size >= 2) over the
ORIGINAL rows that pass the same eligibility check as a single-row cut, each combination tried
against BOTH the cover-cut and the GCD-cut heuristic (`try_cover_cut_on_view`,
`try_gcd_cut_on_view`); capped to instances with <= 12 eligible rows (2^12 subsets is still fast;
this is not a general-purpose separation engine for models with many eligible rows).

MEASURED, not just implemented: after the `is_binary_like` fix above (without it, ALL 4 rows were
ineligible and aggregation never even ran), all 15 subsets of markshare_4_0.mps's 4 rows are
tried every cutting round, and NONE ever produces a violated cover or GCD cut against the root
relaxation's actual fractional point -- confirmed via direct instrumentation during development,
and via an unchanged end-to-end result (`objective=51.999999997`, `best_bound~-2.5e-8`,
~10,400 nodes in 600s) before and after the fix. This is a genuine heuristic-power limitation of
greedy-by-LP-value cover separation, not a bug: the relaxation's actual point does not have
"columns near 1, columns near 0" the greedy heuristic needs to find a violated cover, on any
single row OR any aggregate of them. Closing this would need EXACT minimum-weight-cover
separation (solving a small knapsack per candidate row/aggregate, not greedy) and/or lifting --
both real, known, unbuilt improvements.

**Equality-row absorbing-singleton elimination** (`MilpPresolve.hpp`'s
`eliminate_equality_row_absorbing_singletons`, run before GCD tightening). Both reductions
above require EVERY column in a row to be discrete -- a real problem on markshare_4_0.mps,
where every row mixes ~30 binary columns with one CONTINUOUS "deviation" column, blocking both
rules on every single row. When that continuous column `x_j` is a SINGLETON (appears nowhere
else) with exactly one finite bound, it can absorb any value in its open direction with no
effect elsewhere, so the row `a_ij*x_j + R = b_i` is equivalent to a derived ONE-SIDED bound
purely on `R`. This removes `x_j`'s entry from the row (turning it into an all-discrete
inequality the two rules above can finally use) and replaces the row's equality bounds with the
derived one-sided bound.

`x_j`'s cost is NOT independent -- the row forces `x_j = (b_i-R)/a_ij`, so `c_j*x_j` is really a
function of `R` -- and must be algebraically folded into the remaining columns' own costs and an
objective constant (`c_j*b_i/a_ij - (c_j/a_ij)*R`) before `x_j` becomes a genuine zero-cost empty
column for the EXISTING Presolver (Module 4) to fix arbitrarily. Leaving that fold out was a
real, caught bug: the generic empty-column rule fixed `x_j` at whichever bound minimized ITS OWN
isolated cost, ignoring the row entirely -- markshare_4_0.mps silently reported a confidently
WRONG proof of optimality (`objective=0.0`, provably unreachable) instead of an honest "still
searching." `x_j`'s TRUE value (from the row equation against the FINAL solution, not the
empty-column rule's arbitrary pick) is recovered once at the very end, via
`AbsorbingColumnElimination` records `BranchAndBound.cu` collects during elimination.

Only ever removes one absorbing column per row, and only for a genuine equality (both bounds
finite and equal) -- a ranged/one-sided row with an absorbing column is a separate, rarer case
not attempted here.

**Known, MEASURED limitation on markshare_4_0.mps: the LP bound does not tighten with search
depth, at any node budget tested.** After the absorbing-singleton fix above, the search reports
correctly (no longer a false proof) but still does not converge -- three independent runs at
2,000 / 4,014 / 10,316 nodes (94s / 350s / 600s) all report `best_bound` within [-2.2e-6, -2.5e-8]
of zero, no trend across a 5x range in nodes and 6x range in time. The incumbent DOES improve
with more search (71.0 -> 52.0 across those same three runs, HiGHS's own true optimum is 1.0),
so the search itself is productive -- it simply cannot PROVE any incumbent optimal, because the
bound that would certify it never moves. This is a STRUCTURAL property of this instance (4
constraints spread across 30 binary columns leaves enough freedom in the fractional relaxation
that almost any partial assignment can still be "completed" to near-zero deviation), not a node-
budget shortfall: the 10,316-node run took the full 600s (an average ~58ms/node, each a full GPU
IPM relaxation solve), so reaching the node counts (often 100,000s+) that eventually crack
instances like this would cost hours, on top of the bound needing a fundamentally different
technique to ever move at all.

**Cross-row cutting (above) was built and tried specifically to close this, and confirmed NOT
to.** With the `is_binary_like` fix in place (so all 4 rows are actually eligible this time, not
silently rejected), a `600`-second re-run reports the SAME result as before the fix
(`objective=51.999999997`, `best_bound~-2.5e-8`, ~10,400 nodes) -- the greedy cover/GCD
separation, run against every single row AND all 15 row-combinations, finds zero violated cuts
at the relaxation's actual point, on this instance. So the specific gap this pass closes is
narrower than "cross-row cuts would fix it": what is actually missing is EXACT (not greedy)
separation and lifting, or a fundamentally different bound (e.g. genuine lattice/Frobenius-type
reasoning specific to the generalized-markshare family). Left as an honestly-documented
limitation, not attempted further this pass.

Semi-continuous columns (`VarType::SemiContinuous`) are rejected with `UnsupportedFeature`: they
need a different branching rule ("0, or within [l,u]") than the integer floor/ceil branching
implemented here, and silently treating one as an ordinary bounded column would accept points
the model does not allow.

## 23. Revised Simplex (LP) -- added 2026-09-13

A second, independent LP engine. Host-only: it has no CUDA dependency, which is
what finally makes `cmake --preset release` on native Windows produce a working
`solve` binary and running solver tests. It reuses the existing
canonicalize -> presolve -> scale -> reconstruct pipeline completely unchanged;
`presolve()` and `scale()` are algorithm-agnostic and needed no edits, and
postsolve consumes values rather than a basis, so `recover_solution()` needed
none either.

**Revised simplex is the implementation form; primal and dual are the two
algorithms.** Both are implemented, both share one factorized-basis core
(`src/solver/simplex/detail/SimplexEngine.{hpp,cpp}`), and they differ only in
which variable they choose first:

    dual   -- pick a primal-infeasible BASIC variable (row), then find the
              entering column by a dual ratio test; stays dual feasible.
    primal -- pick a dual-infeasible NONBASIC variable (column), then find the
              leaving row by a primal ratio test; stays primal feasible.

Selected with `--method=dual-simplex` / `--method=primal-simplex`
(`--method=ipm` remains the default). `Options::simplex` holds the tolerances.

Files:

    include/sovsolve/solver/simplex/Basis.hpp          AugmentedMatrix, VarStatus, Basis
    include/sovsolve/solver/simplex/LuFactor.hpp       Markowitz LU + PFI update
    include/sovsolve/solver/simplex/DualSimplex.hpp    dual algorithm + sign derivation
    include/sovsolve/solver/simplex/PrimalSimplex.hpp  primal algorithm
    include/sovsolve/solver/simplex/SimplexResult.hpp  one result type for both
    include/sovsolve/solver/simplex/SolveSimplex.hpp   dispatch + composite handoff
    include/sovsolve/solver/simplex/SimplexSolution.hpp -> model::Solution
    include/sovsolve/solver/LpSolve.hpp                host-only whole-pipeline entry
    src/solver/simplex/detail/SimplexEngine.{hpp,cpp}  shared state and kernels

The mathematics is in `docs/FORMULATION.md` section 12 (augmented working form,
index spaces, the dual sign derivation, the sigma folding, the termination
certificates) and is not repeated here.

### Results

19/19 local Netlib instances reach `Optimal` on BOTH engines with matching
objectives, against 6-7/19 for the IPM. Every objective was cross-checked
against `scripts/oracle_check.py`'s published table, including its two
documented archive-drift entries: `80bau3b` (8.1e-6 drift) and `greenbea`,
where our `-7.2555248130e+07` matches the LP DASA / HiGHS value rather than the
1988 archive's `-7.2462405908e+07`. `gas11` returns `Unbounded` -- the archive
has no ground truth for it and HiGHS also reports unbounded.

Neither engine dominates: `stair` takes 569 primal pivots against 3357 dual;
`80bau3b` takes 5546 dual against 19201 primal. That is the ordinary reason
production solvers keep both, and it is why `--primal-cleanup` (default on)
runs the dual first and hands its basis to the primal.

### Bugs found and fixed during development, kept here because each was a real trap

1. **`Basis::validate()` counted statuses instead of detecting duplicates.**
   `basic = [5,5]` with 5 and 7 both marked `Basic` passes a count check and is
   rank-deficient. Now uses a `seen` bitmap.
2. **PFI drift made `greenbea`'s basis genuinely singular** at every
   refactorization boundary -> `NumericalError`. Fixed with
   `LuFactorization::factorize_repairing`, which on a stalled elimination puts a
   stalled row's LOGICAL into a stalled slot. That logical provably cannot
   already be basic: its column is `e_p`, so if it were basic its slot would be
   a singleton in the active submatrix, Markowitz scores a singleton at zero
   cost, and it would already have been pivoted.
3. **`greenbea` then reported a confident, FALSE `Infeasible`.** An
   infeasibility found inside the artificially-bounded phase-1 problem is a
   verdict about the box, not about the model. Now escalates the box; only an
   infeasibility with no artificial bound in play is a model verdict.
4. **`stair` regressed `Optimal(3357)` -> `MaxIterations(-4.2e7)`** because
   "restore dual feasibility at every refactorization" could install a NEW
   artificial box mid-solve, jumping a nonbasic by 1e7. Split into
   `reflip_dual_infeasible()` (refactorization; re-places only within bounds
   that already exist) and `restore_dual_feasibility()` (phase 1 and after
   repairs only).
5. **Unboundedness needs a JOINT ray.** Testing one column at a time misses
   `min -x-y s.t. x-y<=1, -x+y<=1`. `any_unbounded_ray()` tries the joint
   direction first, then each column alone.
6. **Bland's rule latched permanently**, leaving `greenbea` 1.7 away from
   feasible after 600,000 phase-1 pivots. Bland's is an escape from cycling,
   not a pricing rule to settle into: it is now released on any pivot that
   moves a positive distance. Same instance then solved in 112,421 pivots.

A seventh was a bug in the TEST, not the solver, and is documented in
`tests/unit/primal_simplex_test.cpp` so it is not re-introduced: `min 4a+3b+5c`
with those constraints has a CONSTANT objective (`-8b+3b+5b = 0`), so it cannot
distinguish a correct solver from a broken one.

### Not done in this pass, deliberately

Dual steepest edge, Harris two-pass ratio test, Forrest-Tomlin update and
hypersparse FTRAN/BTRAN are all known improvements over what is here (Dantzig
pricing, a single-pass ratio test with a stability guard, PFI, dense working
vectors with a nonzero list). They are left for a measured second pass, one
technique per commit with before/after corpus numbers, per `docs/BENCHMARKS.md`.
So is the GPU pricing offload for `alpha_r = rho_r' Ahat`, which is to be kept
only if it is measured faster on this corpus.

B&B warm starting (Stage 3 of the plan) is also not done: `BranchAndBound.cu`
still re-runs canonicalize + presolve per node, which can change the canonical
shape between parent and child, and a basis index space cannot survive that.
`BranchAndBound.hpp`'s stated limitation therefore still stands as written.

## 24. PDLP -- primal-dual hybrid gradient (LP) -- added 2026-09-14

A third LP engine, `--method=pdlp`. Host-only. Derived from Applegate, Diaz,
Hinder, Lu, Lubin, O'Donoghue and Schudy, "Practical Large-Scale Linear
Programming using Primal-Dual Hybrid Gradient" (NeurIPS 2021); the restart
machinery's normalized duality gap from the same authors' arXiv 2105.12715,
and the infeasibility certificates from arXiv 2102.04592. The vendored
`or-tools/` tree contains Google's own PDLP; it was NOT read, the same
standard Module 23 applied to `HiGHS/highs/simplex/HEkkDual.*`.

Reuses canonicalize -> presolve -> scale -> reconstruct unchanged. The
formulation mapped with NO conversion, which was the part worth checking
rather than assuming: FORMULATION.md section 4's existing Lagrangian IS the
paper's saddle point (2) with `K = A` and `q = b`. The paper puts inequality
rows first with `y >= 0`; we put equality rows first with `<=` rows and
`y <= 0`. Both differences are absorbed into the projection onto `Y` rather
than by permuting the matrix -- permuting would copy the largest object in the
problem to remove one branch.

Files:

    include/sovsolve/solver/pdlp/TrustRegion.hpp    exact linear-time trust region
    include/sovsolve/solver/pdlp/MatVec.hpp         the K / K' interface
    include/sovsolve/solver/pdlp/Pdlp.hpp           solve_pdlp + sign derivation
    include/sovsolve/solver/pdlp/DualityGap.hpp     normalized duality gap rho_r
    include/sovsolve/solver/pdlp/Infeasibility.hpp  certificates
    include/sovsolve/solver/pdlp/PdlpSolution.hpp   -> model::Solution

Landed in measured stages, one enhancement per commit, because the paper's own
ablation says why: baseline PDHG solves 50 of 383 instances where full PDLP
solves 283. Corpus at a 1,000,000-iteration budget, measured in KKT passes --
the paper's metric, and the honest one here, because the adaptive rule costs
~1.53 passes per iteration against the fixed rule's ~1.03, so iteration counts
overstate every improvement by roughly 1.5x:

    baseline PDHG                    12/19 Optimal
    + adaptive step size (Alg 2)     12/19, 1.04x-3.6x fewer passes
    + adaptive restarts (3.2)        14/19, up to 3.9x
    + primal weights (Alg 3)         17/19, up to 20.6x

Final: 17 Optimal plus gas11 Unbounded. Only `greenbea` is unsolved. Every
converged objective matches the dual simplex's exact answer.

Restarts and primal weights each REGRESSED a handful of already-fast instances
while winning large elsewhere (restarts: six wins up to 3.9x, six losses of
3-16%; primal weights: two losses). Kept as measured rather than tuned away --
the wins are multiples and the losses are percentages.

### Three things the papers got wrong, or left out, found by measurement

1. THE ADAPTIVE STEP SIZE DIVERGES AS LITERALLY STATED. Equation (5) and
   Algorithm 2 line 6 write the acceptance bound with no absolute value, so a
   negative cross term makes it infinite and the step unconditionally
   acceptable. True of one iteration; unsafe across iterations, because
   nothing else bounds `eta` and the growth cap ratchets it up every time the
   sign comes out negative. Instrumenting a free-column LP showed the cross
   term negative for 11 of 12 consecutive iterations while `eta` went 1.0 ->
   8.6 and the iterate diverged to 1.4e20 -- every individual step passing (5).
   Using the MAGNITUDE fixes it, and is what makes the paper's own stated
   property `eta_bar >= 1/||K||_2` informative rather than vacuous.

2. THE DUAL OBJECTIVE'S UPPER-BOUND SIGN IS INCONSISTENT IN THE PAPER. Problem
   (1) writes `q'y + l'lambda^+ - u'lambda^-` while the notation section
   defines `v^-_i = min{0, v_i}`, a non-positive quantity. Together they give
   the wrong sign: `min -x` over `0 <= x <= 1` has optimum -1, and the printed
   formula gives +1. The code was already right, derived from FORMULATION
   section 4 rather than transcribed; only the comment was wrong.

3. THE TRUST REGION SOLVER'S REDUCTION DROPS UPPER BOUNDS. arXiv 2105.12715
   Appendix F states its problem with a lower bound only and reduces to `g > 0`
   by "if g_i < 0 then set g_i = -g_i and l_i = -inf" -- which silently assumes
   nothing stops the coordinate going up. Our box has finite upper bounds. The
   correct reduction REFLECTS instead: `g' = -g_i > 0`, `l' = -u_i`. Verified
   by mutation: the paper's literal version walks a coordinate to the full
   radius 5.0 instead of stopping at its bound 1.0, with no crash and a
   strictly better-looking objective.

### Not done

The GPU backend. The `MatVec` interface exists precisely so a cuSPARSE
implementation can be injected without the host library linking the GPU one,
but it is not written, and the A/B on `datt256`/`ken-18`/`maros-r7` -- the
measurement that would actually answer whether this hardware earns its GPU --
has not been run. PDLP -> simplex crossover is also not done: PDLP tails off
where the simplex returns an exact vertex, so composing them is the natural
follow-on.

## 25. Homogeneous self-dual embedding -- added 2026-09-14/15, `--method=hsd`

Closes a gap README.md names: the interior-point path structurally cannot
report `Infeasible` or `Unbounded`. With no feasible point there is no interior
to follow, so it diverges and the only honest outcome is `MaxIterations` --
`gas11` running away to -7.5e10 is exactly that.

The embedding homogenizes every constant by a scalar `tau` and carries the
duality gap as a scalar `kappa`, giving an always-feasible problem whose
solution answers either way: `tau > 0` means optimal (divide through by it),
`tau -> 0` means the iterate IS a Farkas certificate. Derivation in
FORMULATION.md section 13.

WHAT EXISTS: `solver/Homogeneous.{hpp,cpp}` -- residuals, the complementarity
measure, classification of the final iterate, and recovery. Host-only on
purpose even though the IPM is not, because the load-bearing test has to run in
the default preset with no CUDA toolkit.

WHAT ALSO EXISTS, as of stage 2: `solver/HomogeneousStep.{hpp,cpp}` -- the
iteration control, TRANSCRIBED from

  E. D. Andersen and K. D. Andersen, "The MOSEK interior point optimizer for
  linear programming: an implementation of the homogeneous algorithm", in High
  Performance Optimization, Kluwer, 2000, pp. 197-232.

Algorithmic parameters (Table 1.1), the centering heuristic (1.12), the ratio
test and step size (1.20)/(1.21), the starting point (1.22) and the three
stopping criteria (section 1.4.5, 1.24). Nothing in it is derived.

WHAT ALSO EXISTS, as of stage 3: `solver/HomogeneousNewton.{hpp,cpp}` -- the
bordered Newton solve. `IpmOptions::homogeneous_self_dual` exists, defaults off,
and NOTHING READS IT YET; what remains is an iteration loop calling stage 3 then
stage 2, and the A/B against the direct path.

THE ONE THING THE PAPER DOES NOT GIVE, AND HOW IT WAS CLOSED WITHOUT ONE. [AA]
section 1.2 works in standard form throughout, `Ax = b, x >= 0`. Homogenizing
sends l -> l*tau and u -> u*tau, so with FINITE bounds `tau` appears inside the
complementarity rows `(x - l tau).*z` and `(u tau - x).*v`. Eliminating dz and
dv then leaves dtau terms in BOTH the dual block row and the gap row, and they
are not the same terms -- so the border column and the border row are not
negatives of each other, as they are in standard form.

This was closed by a CHANGE OF VARIABLES, not by a new derivation. The shift

    x = l tau + s1,     s2 = (u - l) tau - s1,     s1, s2 >= 0

carries our bounded embedding onto [AA]'s (HLF) exactly, with s1 = x - l tau,
s2 = u tau - x, y2 = -v, sigma = (z, v), and sigma_I = -y_I on inequality rows
already being standard form. Verified against a dense Jacobian in both
coordinate systems: every block agrees to 1e-15. Two details worth keeping:
the transformed gap row is OURS PLUS A MULTIPLE OF THE DUAL ROW, T3 = -R3 -
l'R2, which is an identity the test asserts rather than assumes; and the c'l*tau
terms from shifting the objective CANCEL against those from shifting the
right-hand side, which is why section 13.1's gap row comes out unchanged -- an
independent confirmation of a row that had only an LP-duality argument behind it.

What comes out, writing Theta_l = Z/(x - l tau) and Theta_u = V/(u tau - x):

    Theta^-1 = Theta_l + Theta_u              section 10.1's diagonal
    D_s      = S/Sigma_I                      inequality rows only
    h_x      = Theta_l l + Theta_u u - c      border COLUMN
    g_x      = Theta_l l + Theta_u u + c      border ROW
    w        = l' Theta_l l + u' Theta_u u    extra trailing term

At l = 0, u = inf: h_x = -c, g_x = +c, w = 0 -- [AA] (1.26). With finite bounds,
measured: ||g_x + h_x|| = 7.14 and w = 17.6.

TWO ORACLES, AND THEY ARE NOT REDUNDANT. Test one transcribes section 13.1 as a
dense Jacobian and factorizes it whole, catching an error in the ELIMINATION.
Test two builds the shifted standard-form instance, writes [AA]'s system verbatim
with no bound terms anywhere in it, maps our direction across and requires it to
satisfy that system -- catching an error in the BORDER ITSELF, which test one
cannot, because test one and the implementation are both derived from section
13.1 and could share a mistake. Confirmed complementary by mutation: with oracle
1 disabled, oracle 2 ALONE still catches a border column that loses its bound
term (failing at the dual row), a border row written as -h_x (failing at the gap
row) and a dropped w (likewise) -- each at exactly the row that term belongs to.

The shift needs finite bounds, since a column with an infinite bound cannot be
shifted by l. Not a hole: such a column has no complementarity pair and so
contributes no bound term, leaving its border entry at [AA]'s -c_j. Oracle 2
covers exactly what [AA] does not, and a third test checks the infinite-bound
case collapses onto [AA] directly.

Converting to standard form in PRODUCTION, rather than only inside a test, was
rejected: it costs 2n + m_I columns and m + n rows, Canonical.hpp keeps bounds
native on purpose, and gas11 is 44% free columns, which the shift cannot express.

COST. [AA] section 1.5: the border solve K(p;q) = (h_x; -b) depends only on the
iterate, so it is solved ONCE PER ITERATION and shared by the predictor and the
corrector; only K(u;v) is per right-hand side. `refresh_border_solve` is a
separate entry point from `solve_homogeneous_newton` precisely so this cannot be
silently lost -- folding it in would double the cost and every test would still
pass. A test counts solves: 1 + 1 + 1 for two directions, not 4.

WHAT THE PAPER CORRECTED IN OUR OWN WRITING. FORMULATION section 13.3 used to
say the bordered system is [K h; -h' k/t] -- the border row being the negated
border column. [AA] (1.26) shows it is not: the column is (-c; -b) while the
row is (-c', +b'), because the second block row carries +A against the first
row's +A'. Writing the solve from -h' puts a sign error on every dtau. The
section now transcribes (1.26)-(1.29) instead. The paper also shows the cost is
LESS than one extra solve per direction: (1.28) is solved once per iteration
and shared by the predictor and the corrector, only (1.29) is per right-hand
side.

WHAT WE HAD TO GENERALIZE, and how each is kept honest. Three formulas are not
[AA] verbatim. Each is marked GENERALIZED in the header next to the
specialization that recovers the published version, and `homogeneous_step_test`
builds an instance that IS in standard form after canonicalization and checks
each generalized formula against [AA]'s equation written out by hand.

 1. The ratio test carries a term standard form cannot see. `tau` scales the
    bounds, so `x - l tau` has direction `dx - l dtau`. At l = 0 it vanishes.
    Omitting it lets a step violate a bound while every coordinate of dx looks
    safe. The test builds a direction where dx is identically zero and only
    dtau moves, so that term is the ONLY thing that binds: deleting it turns a
    finite step into an unbounded one. Confirmed by mutation (1 check, 0.5 vs
    1e30).

 2. rho_A (1.24) uses the full dual objective b'y + l'z - u'v.

 3. [AA] (1.22)'s `y := 0` IS NOT USABLE UNCHANGED, and this one cost a run to
    find. It is admissible only because standard form has no inequality rows
    and so no (s, -y_I) pair. We have them, and at y_I = 0 that pair's product
    is exactly zero -- ON the boundary, not near it -- so the centrality
    condition (1.20) fails at every positive step, the step size returns 0, and
    the solve stalls on iteration one. Measured, not predicted: that is what
    the first run did. Inequality rows now start at y_I = -1; equality rows,
    unrestricted and pairless, stay at 0, so a model with no inequality rows
    still gets y = 0.

ONE PARAMETER HAS NO CITATION: rho_bar_G is used in [AA] section 1.4.5's
infeasibility criterion but is absent from Table 1.1, which lists only
rho_bar_P, rho_bar_D, rho_bar_A, rho_bar_mu and rho_bar_I. It is set to 1e-8 to
match its two siblings in that same criterion, and the field says so.

WHY THE CENTRALITY TEST IS NOT OPTIONAL. [AA]: "if all the iterates satisfy the
condition (1.20), then they converge towards a strictly complementary
solution." Theorems 2 and 3 -- which are what turn a collapsed tau into a named
verdict -- both assume strict complementarity. Skipping (1.20) does not make
the solver slower, it makes the answer unsound.

The Newton system's structure is what makes the rest affordable: homogenizing
adds one row and one column to the SAME matrix `K`, and a bordered system with
a 1x1 trailing block is solved by two solves of the unmodified `K` plus a
scalar Schur complement -- [AA] (1.27)-(1.29). `KktBuilder`, `Ordering`,
`Preconditioner` and `LinearSolver` need no changes at all.

Two tests, catching different things, which is the point of having both. At
`tau = 1` the embedding must reduce to sections 5-6 TERM FOR TERM (expected
values transcribed from the specification, not obtained by calling the direct
implementation -- two implementations of one formula can share a sign error, a
transcription and a derivation cannot). But that test CANNOT catch a missing
`tau` factor, because `tau = 1` makes one invisible; so a second test doubles
`tau` and the iterate and requires every residual to double. Verified
complementary by mutation: dropping the `tau` from `b*tau` leaves all 57
equivalence checks passing and fails 3 homogeneity checks.

Stage 2's tests: 212 checks, proven able to fail by four mutations -- dropping
the l*dtau coupling (1 check), using [AA] (1.22)'s y := 0 verbatim (3), losing
one power of (1-alpha) from the centering heuristic (9), and swapping min for
max in the ill-posed tau test (1).

STAGE 4, the loop and the A/B. `solver/HomogeneousSolve.{hpp,cpp}` runs stages
1-3 in [AA] section 1.4's order, `solver/HostKkt.{hpp,cpp}` supplies the
`KktSolver` they take as an injected interface, and `--method=hsd` selects the
result. One iteration is:

  1. residuals and mu                       stage 1
  2. progress measures, stopping tests      stage 2
  3. the border quantities                  stage 3
  4. K(p;q) = (h_x; -b), ONCE               stage 3, refresh_border_solve
  5. predictor: gamma = 0, eta = 1          [AA] section 1.4.1
  6. gamma from the predictor's step        [AA] (1.12)
  7. corrector: eta = 1-gamma, Mehrotra     [AA] (1.13)
  8. step length, centrality-tested         [AA] (1.20), (1.21)
  9. update

Steps 5 and 7 share step 4's solve, which is why the embedding costs one extra
solve per ITERATION and not per direction. A test asserts kkt_solves ==
3 * iterations on a real run, not just in a stub.

WHY A FOURTH ENGINE AND NOT A FLAG ON THE IPM. The existing interior-point path
is GPU-resident, in sovsolve_solver_gpu, and the gpu -> solver library edge is
one-way (src/solver/CMakeLists.txt). A host-only module cannot be called from
inside it. So this is `Method::Hsd`, sharing the canonicalize -> presolve ->
scale -> reconstruct pipeline with the other three and injecting its own
KktSolver. When a GPU backend exists it supplies a different KktSolver and
nothing in the loop changes.

`IpmOptions::homogeneous_self_dual` was DELETED in this stage. It was added in
stage 1 to mean "run the IPM on the embedding", nothing ever read it, and
selecting the engine now expresses the same intent. A bool with nothing behind
it is exactly the stale-documentation problem this file exists to avoid.

THE LINEAR ALGEBRA is `HostKkt`: eliminate dx from the first block row, giving
(A Theta A' + D_s) dy = ry + A Theta rx, SPD, solved by Jacobi-preconditioned
conjugate gradients that never form the product -- one A'v and one Av per CG
iteration, through the pdlp::MatVec that already existed for PDLP. That is
section 10.1's normal-equations reduction, and it is the same system the GPU IPM
already solves the same way (solve_spd_cg), so the eventual GPU KktSolver is a
port rather than a redesign.

## 26. Irreducible infeasible subsystem -- added 2026-09-14

"This model is infeasible" is a verdict; "these rows contradict each other, and
dropping any one makes the rest satisfiable" is something a planner can act on.
`solver/Iis.hpp`.

Nearly free, because the certificate already existed. Gleeson and Ryan (1990),
as stated in arXiv 1804.01327 Theorem 3.4: for an infeasible `Ax <= b` the
index sets of the IISs are exactly the SUPPORT SETS of the VERTICES of the
alternative polyhedron `{y : y'A = 0, y'b = -1, y >= 0}`. A point of that
polyhedron is precisely a Farkas certificate -- which Module 23 computes as a
byproduct of the pivot that fails, and was throwing away.

"Vertex" is why the DUAL SIMPLEX is required rather than preferred: its
certificate is a row of `B^-1`, hence a basic solution, hence a vertex. The
primal simplex proves infeasibility by phase 1 ending with positive
infeasibility, which yields no such vector; PDLP's is a limit of interior
iterates with no vertex guarantee. `IisQuality` records which guarantee
applies rather than assuming the strong one.

Derived for our form: Theorem 3.4 assumes pure `Ax <= b` with no bounds, while
ours has equality rows (whose multiplier is free in sign, so the support test
is on magnitude) and a box (whose finite bounds can be HALF the contradiction
-- `x <= 3` against a row forcing `x >= 5` is infeasible with no two rows
involved).

Bug found and fixed: the dual simplex proves infeasibility in TWO places, and
capturing only the first left a whole class of models unexplainable. `x >= 5`
against `x <= 3` never reaches the ratio-test exit; it reaches the
bound-flipping exit, where every eligible column was flippable and all of them
together still do not close the violation.

Presolve is disabled for the IIS solve deliberately -- a certificate computed
on the reduced model has its support in the REDUCED row space, so the rows it
names are not the rows the user wrote. Indices are reported in the ORIGINAL
model's space throughout.

Tests assert IRREDUCIBILITY rather than non-emptiness, since returning every
row of an infeasible model is trivially a subsystem and useless: every case
pads the model with satisfiable rows sharing the same variables, including a
three-row cycle where no PAIR is infeasible, and the definition is checked
directly by removing each member and requiring the rest to become feasible.
